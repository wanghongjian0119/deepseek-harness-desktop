# Agent Note: Desktop app packaging (dsh-desktop)

Status: implemented

English | [中文](2026-08-17-desktop-app-packaging.zh.md)

## Problem

The Web GUI is reachable only through `dsh web` (a terminal command that prints `http://127.0.0.1:3080`) plus a browser. The product needs a desktop distribution form: double-click an icon, and a native window opens on the GUI — no Node installation, no terminal, no manual port.

## Decision

### Electron shell over a bundled backend payload

`apps/desktop` (`@deepseek-ai/dsh-desktop`) is an Electron main-process shell that spawns the backend and opens a window at its URL. The renderer is the plain remote web app over `http://127.0.0.1` in a sandboxed, nodeIntegration-free window; the shell owns lifecycle only.

- **Bundled Node runtime, not Electron's Node.** The runtime closure ships prebuilt native addons for standard Node ABIs (`node-addon-require-builtin` publishes per-platform prebuild packages); Electron's embedded Node has a different ABI. The assembler downloads a pinned official Node 22 LTS (`NODE_VERSION`, SHA256-verified) per platform.
- **Payload via the existing deploy-root pattern.** `apps/desktop/deploy-root` is a dependency-only manifest (generated by `scripts/generate-deploy-root.ts`, gated by `verify-runtime-closure`), and the assembler deploys it with the same flags as the Python SDK pipeline: `pnpm deploy --legacy --prod --config.node-linker=hoisted --config.auto-install-peers=false --config.link-workspace-packages=true`.
- **Hoisted linker is required.** The profile module fallback (`healProfilesModuleFallback`) resolves bare plugin rows through `$DSH_HOME/profiles/node_modules` links discovered from the flat installation `node_modules`. In pnpm's isolated virtual-store layout the discovery BFS only reaches the app's direct dependencies (59 links) and the boot fails on the first transitive plugin row; hoisted deploys place the whole closure at the top level (189+ links) and the heal completes.
- **The deploy root lists every workspace peer explicitly.** `pnpm deploy --prod` drops workspace peers that are also devDependencies of their owner (`dsh-timeout`, `dsh-invariants`, `cordis-plugin-group`, the `dsh-session-title-*` pair, …), failing the boot loud at the first missing import. The generated root lists dependencies + peers + optional dependencies of every closure member, and `verify-runtime-closure` (wired into `hygiene` as `verify-runtime-closure:desktop`) enforces it.
- **extraResources, never asar, for the payload.** A separate Node process cannot read asar, and the profile fallback creates symlinks into the payload; electron-builder ships the payload unpacked under `Resources/dsh`. The dependency closure lives at `runtime/node_modules` inside the payload because electron-builder's extraResources copy hard-excludes a source root's own `node_modules` directory (nested ones pass through); the dsh CLI is deployed as part of the closure (`runtime/node_modules/@deepseek-ai/dsh`), so no manual copy is needed.
- **Port 0 + readiness line.** The backend runs `web --port 0`; the shell parses the existing `dsh web: http://127.0.0.1:<port>` stdout line (the supervisor contract already documented for the keyless CLI smoke) and loads that URL. No port conflicts, no fixed-port probing.
- **Lifecycle.** Closing the window quits the app on every platform (v1 has no tray); `will-quit` stops the backend (SIGTERM → 5s → SIGKILL, `taskkill /t` on Windows) with a sync SIGKILL fallback on `process.exit`; a backend that dies or fails to boot surfaces a dialog with Restart/Quit; a second instance focuses the existing window.

## Alternatives considered

- **Electron's embedded Node** — avoided entirely because of the native-addon ABI mismatch; every payload build downloads its own Node runtime.
- **macOS notarization** — unsigned builds need right-click → Open; signing and notarization are future work.
- **Tray / dock persistence** — the app is its window; closing it stops the backend. A tray keep-alive is deferred.
- **Per-platform payload pruning** — the payload (~300–400 MB) ships the whole closure on every platform; dropping the headless/pwsh stacks per target is deferred.
- **Auto-restart of a crashed backend** — v1 offers a Restart button instead.

## Consequences

The packaging buys an open-and-use desktop distribution: the app is fully self-contained (Node runtime, CLI, closure, frontend), needs no host prerequisites, and uses an OS-assigned port so it never collides with a checkout running `dsh web` on the default port. `$DSH_HOME` stays the shared default (`~/.dsh`), so CLI and desktop sessions, settings, and credentials remain one user state.

The costs: every payload build downloads its own Node runtime and must run on the target platform (native addons and the runtime are platform-specific); the payload is ~300–400 MB before the Electron shell; macOS builds are unsigned until signing and notarization land; the app is its window, so closing it stops the backend with no tray keep-alive; and the deploy-root manifest must be regenerated and re-gated whenever the CLI dependency graph changes.

## Verification

- `verify-runtime-closure --manifest apps/desktop/deploy-root/package.json` passes: 192 workspace packages form a closed graph.
- `scripts/assemble-payload.ts` ends with a keyless boot smoke: it runs the staged CLI over a scratch `$DSH_HOME` with `--port 0`, waits for the readiness line, and asserts `GET /` carries the `__DSH_BOOT__` boot manifest (`window.__DSH_BOOT__` or upstream `globalThis["__DSH_BOOT__"]`).
- Unit tests cover the readiness-line parser, the readiness wait (URL line, early exit, stream end, timeout), stop escalation, and payload resolution.
- Reproduce: `pnpm run build`, `pnpm install`, then `pnpm --filter @deepseek-ai/dsh-desktop run build:payload` (network: Node runtime download) and `pnpm --filter @deepseek-ai/dsh-desktop run dev`.
